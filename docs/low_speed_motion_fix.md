# RS 低速轨迹控制修复方案

针对保持末端姿态、z 方向上升 0.1 m、运动时间 8 s 的场景。修改的是
`controllers`、`trajectory`、`kinematics` 和 `actuator` 核心实现；示例只增加诊断入口。

## 1. 控制链路

```text
新鲜关节位置 → 当前末端位姿 → 均匀空间采样 → 连续种子 IK
→ 校验每个解 → 五次多项式几何路径 → 插值路径校验
→ 最小 jerk 时间参数化 → 必要时延长运动时间
→ 每个真实控制周期计算 q_ref、qd_ref、qdd_ref
→ MIT: q_ref + qd_ref + 重力前馈 + 可选摩擦前馈
```

同一条路径的空间采样不依赖 2 s、8 s 或更长的执行时间。
轨迹执行不再由一个线程每 10 ms 修改目标角度、另一个线程重复发送。

## 2. 源码改动与目的

| 文件 | 改动 | 解决的问题 |
|---|---|---|
| `trajectory/clik_tracker.py` | 空间增量相关的收敛容差、连续种子、步长上限、活动限位、下降线搜索；冻结未控制的夹爪关节 | 低速目标落入固定容差而被吞掉；迭代跳变和错误裁剪 |
| `trajectory/clik_tracker.py` | 限位梯度有界；可选修正采用 SVD 真零空间；硬件笛卡尔运动默认关闭此修正 | 原来的 `1/distance` 梯度和阻尼伪投影污染末端路径 |
| `trajectory/joint_reference.py` | 五次插值匹配位置和两阶导数，解析计算速度、加速度，检查整段多项式的限位与导数极值 | 位置目标阶梯、不一致的目标速度、插值越限 |
| `controllers/rebotarm_endpose_controller.py` | 直接对目标末端位姿规划；检查全部 IK 成功、关节跳变、插值路径偏差和纯竖直运动的反向 | 失败或不连续的关节轨迹直接进入电机 |
| `controllers/rebotarm_endpose_controller.py` | 控制周期内按单调时钟采样；首次发送时开始计时；IK、重力和日志各自使用独立 Pinocchio Data | 两个发送时钟漂移、规划/控制共享数据 |
| `controllers/position_feedback.py` | RS `mechPos(0x7019)` 独立线程低频读取，有请求超时与本地时间戳；读取失败保留旧时间戳 | 过期缓存被当成新反馈；同步读取拖慢伺服循环 |
| `actuator/rebotarm.py` | `request_feedback=False` 不再触发参数兜底读取；严格发送模式、错误计数；真实 dt 和超周期统计 | 隐藏阻塞、发送失败无记录、假定周期恒定 |
| `kinematics/inverse_kinematics.py` | 限制数值迭代步长、冻结未控制关节、SE(3) 对数误差雅可比修正 | 终点 IK 与轨迹 IK 的约束处理不一致 |
| `trajectory/sampler.py` | 修复梯形曲线归一化速度，提供解析时间曲线导数 | 梯形曲线原先可能越过终点后跳回 |
| `config/rebotarm_rs.yaml` | 新增运动约束、反馈、诊断和摩擦配置；RS 默认发送频率 250 Hz | 给回复帧和参数读取留总线余量 |

依赖下限更新为 motorbridge 0.5.0，锁文件已有的 0.5.0 版本保持一致。反馈使用
`robstride_get_param_f32_host_id` 指定配置中的主机 ID；普通 getter 会把超时提升到
至少 150 ms 并探测备用 ID，不适合这个有界反馈线程。

## 3. 摩擦死区与爬行

核心控制器新增可选、有界的静摩擦 / Stribeck / 库仑 / 黏性摩擦前馈：

```text
magnitude = coulomb + (static - coulomb) * exp(-(qd_ref / stribeck_velocity)^2)
tau_friction = clip(magnitude * tanh(qd_ref / velocity_scale)
                    + viscous * qd_ref, -limit, +limit)
```

方向取自连续的参考速度，避免用 RS 未确认量纲的 `mechVel` 或量化差分速度来切换符号。
参考速度为零时摩擦项为零；`static >= coulomb >= 0`，并有每关节摩擦限幅和总前馈限幅。
总前馈采用 20 ms 一阶滤波，减小低频反馈更新和补偿变化带来的力矩阶跃。

摩擦补偿默认关闭，所有摩擦系数初值为零。仓库已有的一台机器标定结果不能直接
当成另一台机器的静摩擦参数；也不能把库仑摩擦当成起动力矩。

实机标定与启用顺序：

1. 先保持摩擦补偿关闭，验证新参考轨迹和反馈时间；检查关节零点、负载和接触情况。
2. 用仓库 `tools/gravity_calibration` 中的低速往返扫描工具，按实际装配和负载估计
   重力偏差、库仑摩擦；静摩擦需另外测量起动时的额外力矩。
3. 将本机的六个关节结果填入 `friction.coulomb/static/viscous`。`static` 不得小于
   `coulomb`；`velocity_scale` 与 `stribeck_velocity` 单位为 rad/s，需根据低速扫描调节。
4. 分关节、从较小补偿比例开始验证，再启用 `friction.enabled`。观察慢速正反向运动及停止后
   的位置偏差；用日志确认补偿没有引入新的反向或到位漂移。
5. 在参考、反馈和摩擦模型确认后，再按关节惯量与负载调整 MIT Kp/Kd。这里保留原配置
   增益作为起点，未把增大 Kp 当成摩擦死区的通用修复。

默认速度上限为每关节 0.5 rad/s，加速度上限 1 rad/s²。若请求时间不足，
`allow_retime: true` 会延长时间并报告实际时长；设置为 false 则拒绝该动作。
限位检查采用多项式极值，速度和加速度使用保守解析上界；笛卡尔插值误差检查每段包含
四个区间，是密集数值检查，不是对整段末端路径的数学证明。

## 4. 实机复现与验收

启动已有脚本：

```bash
python example/8_arm_traj_control.py
```

在已经稳定、且整个上升路径有空间的起始位姿下输入：

```text
lift 0.1 8
```

该命令读取当前位姿，在世界坐标系向上平移 0.1 m，并保持测得的姿态。
避免手动填入默认零 RPY，导致“升高”同时变成“改变姿态”。

运动完成后、退出前：

```text
status
log lift_10cm_8s.csv
```

`state` 和 `end_state` 的机械臂位置也改为读取控制器同一份新鲜反馈，
避免诊断命令显示 SDK 旧缓存而与控制日志不一致。

日志包含 `z_ref/z_actual`、六个关节的参考位置/速度/加速度、反馈位置、前馈力矩、
控制间隔、反馈年龄、发送错误及故障信息。`z_actual` 是关节反馈正解，不能检测结构变形、
齿隙等编码器之外的末端偏移。反馈约 25 Hz 更新，日志约 50 Hz，重复反馈点是正常的。

验收重点：

- `z_ref` 单调上升，终点偏差在配置容差内；`qd_ref` 随运动连续变化，起止为零。
- `actual_duration` 符合请求或已报告的延长时间。
- `z_actual` 是否仍然反向；若参考正确而反馈反向，重点查关节误差与本机摩擦/增益。
- 无反馈超时、发送错误或控制间隔故障。
- 调整摩擦补偿后，起步、收尾及到位保持均需验证。

## 5. 故障与 API 行为

- 初始位置来自真实反馈，首次目标不再默认为全部零位。
- 运动进行中拒绝新的运动命令，避免用不连续的参考替换当前轨迹。
- `stop` / `stop_motion()` 清除参考速度，并请求保持测得的位置。这是快速保持，
  不是有制动距离规划的受限减速轨迹。
- 反馈过期、控制周期超限、跟踪误差超限或发送失败，会撤销运动并持续尝试位置保持。
  总线断开时软件无法保证保持命令送达，最终行为由驱动器与硬件决定。
- 故障不会自动继续旧动作。确认状态后可用 `clear_fault`，然后重新规划。
- `move_to_ik()` 现在也采用平滑关节运动，默认 2 s，不再一步切换关节目标。
- 省略 RPY 的 `move_to_traj()` / `move_to_ik()` 保持当前姿态；显式传入三个 RPY 则按目标姿态运动。
- 硬件末端控制器要求 MIN_JERK；通用轨迹采样模块仍支持 LINEAR/TRAPEZOID。
- `safe_home()` 复用同一执行器；存在故障时跳过自动归零。`end()` 是用户请求的结束与断开操作。
- RS 使用实际参数读取得到反馈年龄；motorbridge 0.5 的 DM 状态没有硬件时间戳，
  对 DM 缓存的本地读取时间不能证明硬件反馈新鲜程度。

## 6. 已做验证与限制

测试覆盖参考导数一致性、两阶导数连续性、限幅/时间缩放、梯形曲线、极小空间增量逆解、
零空间隔离、RS URDF 的保持姿态上升 10 cm / 8 s、不可达目标拒绝、反馈超时、
发送失败、长控制周期、反馈时间戳和摩擦限幅。

后续已经在临时独立的 Windows / Python 3.11 环境安装 conda-forge 原生 Pinocchio，
完成了真实 URDF 的轨迹、动力学及数值求导验证。具体原生接口错误、修复和验证结果见
[原生 Pinocchio 审查](native_pinocchio_review.md)。仍未进行实机验证，
不能据软件测试通过宣称物理抖动已经消失。

在项目支持的 Python 3.10/3.11、具有原生 Pinocchio 的环境中复核：

```bash
python -m pip install pytest
python -m pytest tests -v
```

测试默认要求原生 Pinocchio，并在报告头显示后端版本；缺少原生库会失败，
不会自动降级。只有显式指定 `--offline-kinematics` 才使用 NumPy 测试替身，
此时原生动力学测试会跳过。
RS CAN 指令量化分辨率约 0.022°，固件内部速度估计、机械摩擦和增益仍需实机验收。
