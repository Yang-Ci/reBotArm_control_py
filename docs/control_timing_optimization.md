# 低速控制的进一步优化与调参顺序

这轮继续审查了轨迹采样、反馈、Pinocchio 计算、控制调度和日志。
RS 仍按原配置 250 Hz，DM 仍按原配置 500 Hz；没有通过降低指令频率解决问题。
以下软件改动已完成，实际机械臂的摩擦、增益和负载仍需真机日志确认。

## 已完成的优化

| 改动 | 位置 | 作用及边界 |
| --- | --- | --- |
| 轨迹导数系数提前计算 | `trajectory/joint_reference.py` | 规划时缓存一、二阶导数系数，周期采样直接使用；q/qd/qdd 的曲线不变 |
| 重力按新反馈更新 | `controllers/rebotarm_endpose_controller.py` | 同一反馈快照只计算一次 g(q)；新序号到来才更新。摩擦前馈和力矩滤波仍每周期计算 |
| 日志 FK 移到导出阶段 | 同上 | 周期内保存当时的关节快照；导出时用独立 Pinocchio Data 计算参考/实测 Z，CSV 列保持兼容 |
| 超时仍沿原时间基准调度 | `actuator/rebotarm.py` | 过期周期跳过，下一次运行落在原来的周期网格上；避免每次超时重设基准造成累计漂移，不连续补发旧指令 |
| 全周期时序统计 | 同上及 `tools/analyze_motion_log.py` | 增加周期 P50/P95/P99/P99.9、最长回调和错过的周期数；分析器同时检查平均频率及 P99 |
| 并发反馈读取串行化 | `controllers/position_feedback.py` | 启动、手动刷新和后台采集不能重叠请求，防止旧批次晚完成后覆盖新批次；控制循环读取已发布快照，不等待这个采集锁 |

重力缓存依赖已发布的反馈序号，启动和清除故障时会失效重算。
它减少重复计算，不改变反馈采集频率，也没有新增较慢的力矩滤波。
导出会使用记录时的关节值，随后关节变化不会改变历史日志。
导出仍会使用主机 CPU，应在一段动作完成后进行。

## 如何检查时序优化

按 [RS 真机验证](hardware_validation.md) 或 [DM 串口桥验证](dm_low_speed_motion_fix.md)
运行只读预检、静止记录、单关节探测和逐级升高测试。运行 `status` 或导出日志后查看：

- `control_loop.target_rate_hz` 与 `achieved_rate_hz`：运行满 1 s 后，平均达到目标的 90% 是初步筛查条件。
- `control_loop.control_dt_s.p99`：初步条件为不超过两个名义周期。DM 500 Hz 对应 4 ms，RS 250 Hz 对应 8 ms。
- `max_callback_s`、`max_dt`、`missed_deadlines`：平均频率正常也可能有偶发长暂停，需要结合最大值和故障一起看。
- 反馈年龄、读批次跨度、发送错误：周期正常不能证明报文及时到达电机。

全周期分位数使用固定大小直方图，区间宽度为 10 µs，超过 100 ms 的数据进入溢出桶；
落入溢出桶的分位数保守报告实测最大值。这是诊断统计，不是实时性保证。
它统计本次控制线程运行的全部周期，`record` 或新轨迹不会清除历史时序统计；
独立比较两套配置时，应分别重启控制器，保存对应日志。
CSV 的 `control_dt` 仍只来自日志采样周期，不能代替状态 JSON 的全周期统计。

```text
python tools/analyze_motion_log.py logs/dm_lift_8s.csv --expected-dz 0.1 --output logs/dm_lift_report.json
```

同一分析命令也适用 RS 的相应日志。这里的 90% 与两个周期是诊断起点，
不表示达到这些值后物理抖动一定消失，也不表示测到了 USB/CAN 的实际送达时刻。

## 真机上的下一步

按下列顺序进行，保持起点、负载、控制模式一致，每次只改一类参数。

1. **先查静止保持和重力模型。** 记录 10 s 静止状态，在几个允许的姿态比较关节误差和 Z 波动。
   姿态变化后误差明显改变时，优先核对关节零点、轴向、连杆质量/质心以及夹爪和末端负载。
   URDF 必须与实际机构一致；默认重力前馈不能自动识别额外负载。
2. **再逐轴调增益。** 从关节 2、3 的小幅正反向运动开始，比较跟踪误差、到位过程和静止波动。
   MIT 调位置刚度/速度阻尼；POS_VEL 要检查驱动器内部位置、速度环和积分参数。
   没有这些测量前不统一提高 Kp 或叠加外环积分。
3. **然后辨识低速摩擦。** 时序正常、参考平滑，但关节慢速运动出现“滞留后跳动”时，
   比较相同位移的正反向运动和不同持续时间，再逐轴拟合有限幅度的静摩擦/库仑/黏性参数。
   现有 MIT 的平滑摩擦前馈可使用测得参数；默认仍关闭。POS_VEL 不传递这项力矩前馈。
4. **最后判断是否继续下沉控制循环。** 若全周期 P99 和最长暂停仍明显超标，
   先测出耗时来自主机调度、Python 回调还是串口/适配器写入。
   主机执行确为瓶颈时，可把周期采样和发送搬到原生线程，Python 保留规划和命令接口；
   若瓶颈在板子缓存或 CAN，这个重构本身不能解决传输延迟。本轮没有实施这个重构。

完整动作按 1 cm / 2 s、5 cm / 4 s、10 cm / 8 s 逐级验证。
最后在相同起点比较 10 cm / 4 s、8 s、16 s，检查爬行是否随速度改变。
运动持续时间是诊断变量，控制发送频率保持不变。
末端柔性和减速器间隙可能不体现在电机编码器 FK 中，需结合实际末端观测。

## 验证结果

- Windows / Python 3.11 下，原生 Pinocchio 3.9.0 与 4.1.0：各 111 项通过。
- 显式替身模式：84 项通过、27 项原生测试跳过；不作为原生动力学验证。
- 既有 motorbridge 0.5.6 原生补丁：此前 53 项 Rust 测试通过；本轮没有修改原生补丁。

新增回归检查固定周期网格、重力计算次数与持续滤波、控制回调不运行日志 FK、
导出使用历史快照、并发反馈发布顺序，以及平均频率正常但 P99 异常时分析失败。
这些测试不连接总线；尚未在真机以及 Ubuntu/macOS 上运行本轮控制验证。
